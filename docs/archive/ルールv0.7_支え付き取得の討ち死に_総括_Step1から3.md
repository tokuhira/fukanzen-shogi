# 不完全将棋 ルール v0.7 支え付き取得の討ち死にアーク 総括（Step 1〜3）

*この文書は、v0.6 が掲げながら同時着手化で空文になっていた方針1「損得勘定の維持」を、支えのある駒を取ると取りに行った駒が討ち死にする規則で回復した一連の実装（Step 1〜3、配布 v0.12.3→v0.13.0、`RULE_VERSION` 0.6→0.7）の総括である。段ごとの詳細は各実装指示書（`archive/implementation/rule-v0.7-support-forfeit/`）にあり、設計正本は `design/不完全将棋_ルール仕様_v0.7` §4.8・`design/不完全将棋_ルール版の系譜と対局モード_方針` §1.6。ここは道のり・確立した設計・確定した判断・残された次の畝を粗く俯瞰する地図。なお本アークは、上位設計の相談を Claude Code 内 Opus へ寄せた初回でもある——相談→ドラフト→正本→Sonnet 実装→Opus レビュー→deploy が一周した。*

---

## 0. このアークが始まった地点と、達成したこと

**始点**: v0.6 は §0 設計方針の筆頭に「損得勘定の維持」を掲げていたが、手番を廃した同時着手が**取り返しを次ターンへ繰り延べ・回避可能に**したため、支えのある駒を取っても即時の代償が生じず、損得が働かなかった。§0 中核命題自身が「投機が駒得の主経路」と、方針1 の降格を認めていた。犯人は派手な 4.5 相討ち（交換）ではなく、地味な **4.1 取得**——留まった駒を取る際、支え（守りの利き）が取得に何の代償も課さないこと——だった。

**終点（現在）**: 4.1 取得で、**移動完了時点**の取り合いマス S への利き数を比較し、守り側 d が攻め側 a を上回るとき（**d ＞ a**）取りに行った駒を相手の駒台へ**没収**する（対局者向けノーテーション「**討ち死に**」）。取得そのものは成立（取った駒は自分の駒台へ）、**a ≧ d は通常取得のまま**、玉は対象外、相討ち（投機の手段）は無変更。`RULE_VERSION` 0.6→0.7、配布 v0.12.3→**v0.13.0**（バージョン互換性方針の初の実タプル bump）。埋め込み版は engine ソースから本番 `_bg.wasm` まで sha256 一致で検証済み。

**確立した設計パターン**:
- **一つの規則が二方針を担う**: 没収が方針1（取り返しの代償で損得回復）を、利きを守り以上に足せること（突破）が方針3（膠着打開への報酬）を、同じ規則の中で果たす。別建ての反停滞層（backstop・点数）を作らず捕獲規則へ内蔵した（案A）。
- **討ち死には engine（盤の理）の領分**: 投了・時間切れが protocol の終局なのと対照的に、討ち死には 4.1 取得の帰結＝盤面の出来事なので `engine::resolve` に置く。終局判定の単一正本化が protocol へ寄せた投了とは層が違う。
- **(b) 串刺し計数**: 取り合いマス S を空けた盤で両側を数え、S の裏に控えた走り駒（後詰め）を攻守対称に計上する。`piece_attacks` が味方駒で止まる非対称（守りは取られた駒が消えて透ける／攻めは取った駒に遮られる）を、S を透かすことで解消——大駒・香を後ろに重ねる積極策が正当な突破の投資として報われる。
- **用語の分離**: 機構・コードは forfeit／没収（field 名・event key）、対局者向けノーテーションは「討ち死に」。
- **家元システムでの宗家前進**: v0.7 は宗家（canonical な一本）の最初の前進。v0.6 は葬らず `archive/rule-history/` に残す。

## 1. 機構と API（`engine`・`engine-wasm`、Step 1・2 で新設）

| 型・関数 | 役割 |
|---|---|
| `engine::movegen::count_attackers(pos, sq, side) -> usize` | side の駒が sq に利いている枚数。呼び出し側は sq を空けた盤を渡す（(b) 串刺し）。`piece_attacks` を回すだけ。 |
| `engine::resolve::resolve_independent` の没収分岐 | 移動完了時点の盤を S ごとに空けて両側 d/a を**先に数えてから**適用（双方同時没収でも順序独立）。d>a かつ取った駒が非玉なら、取りに行った駒を相手の駒台へ（`unpromoted()`）・S を空ける。 |
| `ResolutionEvent::Normal { …, sente_forfeit, gote_forfeit }` | 没収された駒種を載せる 2 フィールド（Step 1 で拡張）。他の構築・match 箇所は `..` で追随（cli 含む）。 |
| engine-wasm `resolve` の `event:"forfeit"` | 没収時の web への cue。`web/view-model.js` の `EVENT_LABEL` が「討ち死に」と表示。events 配列・観戦者の wasm 再計算を通じ live／再生／観戦すべてに一箇所で波及。 |

相討ち（`resolve_clash`・`resolve_king_wins`、Case 1/2）は本アークを通じて**一切変更していない**——討ち死には 4.1 取得（`resolve_independent`）にのみ生じる。

## 2. 段ごとの道のり（course-grained）

**Step 1（engine 核・要石）**: `count_attackers` を movegen に追加、`ResolutionEvent::Normal` を没収 2 フィールドで拡張し全構築/match を追随（私の grep が漏らした `cli` の `print_resolution` を Sonnet が自力で拾った）、`resolve_independent` に没収分岐（(b) 串刺し・両側先に数えてから適用・非玉ガード）、`RULE_VERSION`→0.7、破れる 2 テスト文字列を 0.7 へ。table テスト 6 本（浮き駒＝没収なし・支え一枚＝没収・利き足し＝没収なし・玉ガード・双方同時没収・(b) 後詰め対称／非対称）。`cargo fmt`/`clippy`/`test` の 3 点でワークスペース緑。配布・web `?v=` 据え置き。

**Step 2（表示 fast-follow）**: TUI `build_resolution_text` に討ち死に行、engine-wasm `resolve` が没収時に `event:"forfeit"` を返す一点、`web/view-model.js` の `EVENT_LABEL` に「討ち死に」。棋譜の一手表記（`ja_notation`）は ply の帰結でないので無変更。wasm 再ビルド・web `?v=` 0.12.9・vitest 132 緑。**実ブラウザ＋本番 WS＋観戦で「討ち死に」cue を目視**（Sonnet が実環境で受け入れ条件網羅を申告）。配布据え置き。

**Step 3（ルール正本の版上げ＋deploy）**: `design/不完全将棋_ルール仕様_v0.7.md` を新設（v0.6 を土台に §0 中核命題の更新・§4.8「支え付き取得の討ち死に」・§6 差分・§7 点数制の観測条件・改訂履歴）、`v0.6` を `archive/rule-history/` へ `git mv`、README の A/B-1 を v0.7 へ。TUI リリース・wasm 再ビルド・`wrangler` 本番デプロイ、配布バイナリ 0.12.3→v0.13.0。この段は指示書化せず直接着地。**本番 `protocol_wasm_bg.wasm` に焼き込まれた版が 0.13.0 で、ローカル(コミット済み)と sha256 一致**することを curl で確認（proxy の package.json でなく実体で）。

## 3. 確定した判断（再燃防止・re-litigate しない）

- **案A（利き数のみ）vs 点数制**: v0.7 は利きの数だけで置く。谷川値等の点数制は、方針3 が余りにも損なわれた——局所の利き優位を作れず相互不動へ収束し引き分けが決着を圧倒する——が**プレイテストで観測されてから**、まず分家 `0.7-点数` で試す（§1.6 観測条件）。今は開かない。
- **(b) 串刺し vs (a) スナップショット**: (b) を採用（後詰めを攻めに使えることで大駒・香の価値を活かし積極前進を報いる）。(a)（S を空けず素の `piece_attacks`）の攻守非対称は意図的に採らなかった。
- **X-b（置換）vs 版ディスパッチ併存**: v0.7 は置換で最小着地（`RULE_VERSION` を上げ `resolve_independent` を差し替え）。版ディスパッチ＝legacy-play は「実際に旧版で指したくなったとき」へ繰り延べ（§1.5 を当初の「最初の変更に付随」から改訂）。v0.6 は仕様と git に残るので葬られない。近ゼロの書庫では忠実再生の実損なし。
- **討ち死に＝engine 層 vs protocol 層**: engine（4.1 取得の帰結）。盤の理なので `resolve` に置く。投了・時間切れ（protocol）とは別。
- **玉は没収対象外**: 移動完了時点判定ゆえ玉取得で d>a が成立しうるが、玉は駒台に載らない＝5.2 玉の死の領分。非玉ガードで排他（Step 1 の v0.7-3 テストがこの一線を固定）。

## 4. 既知の限界と次の畝

- **方針3 の観測**（本アークの果実を待つ本命）: deploy 済みなので、実戦（人・AI）で「利き優位の突破」が膠着打開の駆動源として足りるかを観る。相互不動・引き分け濫用が出れば点数制（分家）へ。→ §1.6 観測条件・バックログ §B。
- **レガシー対局（v0.6 で指す）**は版ディスパッチ待ち（legacy-play の必要が生じたとき）。→ バックログ §E・方針 §1。
- **利き数の簡略化**: 駒の値・多段の取り合い順序は見ない純粋な枚数勝負。従来将棋の取り合い計算と食い違う値配置がありうるが意図した簡略化で、点数制がそこを精密化する候補。

## 5. このアークで効いた流儀（次の Opus・実装者へ）

- **上位設計を Claude Code 内へ寄せた効き**: 相談で設計を詰めたその手で `docs/` に据え、engine の現物（`RULE_VERSION` が単一定数・`resolve` が版を取らない・`piece_attacks` が味方で止まる）を直接 grep してから設計判断（(b) の非対称・X-b・玉ガード）を下した。別チャットへ状況を要約して渡す往復と、二重のリポジトリ確認が消えた。想像で書けば外していた所を、現物が救った。
- **版の埋め込みは proxy でなく実体で確認する**: 「wasm に古い版が焼き込まれないか」の懸念に対し、package.json（wasm-pack の生成物＝proxy）でなく `_bg.wasm` を `grep -a` し、さらに**ローカル(コミット済み)と本番の sha256 一致**まで取って source→本番の一気通貫を証明した。「ここからは見えない」と punt せず curl で本番を一次確認する（→ memory feedback）。
- **探索範囲を絞りすぎない**: レビュー中、`recordInviteAsked` のリセットを board.js だけ grep して「毎局出ないバグ」と誤診し、reducers.js の `resetOnlineReduce()` にある reset を見落とした。完全網羅の確認では対象ファイル・出力を切り詰めない。
- **版の目盛り**: engine 核（挙動は v0.7 だが配布据え置き）・表示（`?v=` のみ前進）・版上げ+deploy（配布 bump）——「出来事＝配布版が動く」の原則を貫き、対戦互換を壊す変更（ルール版 up）を初めてメジャー級として配布に刻んだ。
