## 1. TUI — `build_resolution_text` に没収の行（`tui/src/app.rs`）

`ResolutionEvent::Normal` の match で `..` を `sente_forfeit`/`gote_forfeit` の束縛に替え、取得の行の**後**に没収の行を足す。

```rust
ResolutionEvent::Normal {
    sente_capture,
    gote_capture,
    sente_forfeit,
    gote_forfeit,
} => {
    // …既存の取得／戦国無双の行（無変更）…
    if let Some(k) = sente_forfeit {
        lines.push(format!("先手の{}が討ち死に（支えに取り返され後手の持ち駒へ）", piece_kind_ja(k.unpromoted())));
    }
    if let Some(k) = gote_forfeit {
        lines.push(format!("後手の{}が討ち死に（支えに取り返され先手の持ち駒へ）", piece_kind_ja(k.unpromoted())));
    }
    // 「取得なし」分岐は現状のまま（没収があるときは取得も伴うのでここには来ない）
}
```

- 文言は既存の口調（「先手が○を取得」）に合わせた。表記は `piece_kind_ja(k.unpromoted())`。
- **呼び出し側を確認**: `build_resolution_text` がローカル対局・オンライン対局の双方で使われること（没収がどちらの経路でも表示されるよう）。
- テスト: TUI に `build_resolution_text` のテストがあれば、支え付き取得の没収局面で没収行が出ることを固定。無ければ最小限で追加（無理に増やさない）。

## 2. web — engine-wasm の event 拡張とラベル

### 2.1 engine-wasm（`engine-wasm/src/lib.rs:44-50`）

`Normal` の枝で、没収が一つでもあれば `"forfeit"`、無ければ従来どおり `"normal"`：

```rust
let event = match &resolution.event {
    engine::resolve::ResolutionEvent::Normal { sente_forfeit, gote_forfeit, .. } => {
        if sente_forfeit.is_some() || gote_forfeit.is_some() { "forfeit" } else { "normal" }
    }
    engine::resolve::ResolutionEvent::Clash { .. } => "clash",
    engine::resolve::ResolutionEvent::SenteDied => "sente_died",
    engine::resolve::ResolutionEvent::GoteDied => "gote_died",
    engine::resolve::ResolutionEvent::BothDied => "both_died",
};
```

- 一手一文字列の粗い cue（両者没収でも "forfeit"）。どちらの駒がどう没収されたかは盤・駒台の変化で見える。cue の目的は「支え付き取得が起きた」と気づかせること。
- JSON の他フィールド（`sfen`）は無変更。web は従来どおり SFEN で盤を描く。

### 2.2 web ラベル（`web/view-model.js:8-13`）

`EVENT_LABEL` に一行足すだけ（`eventText` の :76-77 は non-'normal' を表示するので "forfeit" は自動でラベル化）：

```js
const EVENT_LABEL = {
  clash:      '相討ち',
  // …既存…
  forfeit:    '討ち死に',
};
```

- **event key は内部語 `"forfeit"` のまま、表示ラベルだけ「討ち死に」**（用語の分離）。`events` 配列（game-record.js）が "forfeit" を貯め、再生・巻き戻しでも出る。観戦者は wasm 再計算で "forfeit" を得るので**自動追随**（別途の観戦コードは不要）。

## 不変の原則

- **用語の分離**: コード・機構は `forfeit`／没収（field 名 `sente_forfeit`・`gote_forfeit`、engine-wasm の event key `"forfeit"`）のまま。**対局者向けのノーテーション（TUI 行・web ラベル）は「討ち死に」に統一**する。内部の具体語と、盤上の物語る語を分ける。→ 方針 §1.6。
- **表示のみ・ルール無変更**: 没収の論理は Step 1 が正本。この段は見せるだけ。
- **一箇所で波及**: web は engine-wasm の event を "forfeit" にする一点で、live・再生・観戦へ届く（観戦者も wasm 再計算）。
- **最小の cue**: 一手一文字列の粗い印。詳細は盤・駒台が語る。凝らない。
- **per-move 表記に混ぜない**: 没収は ply の帰結。ja_notation は無変更。
- **実地検証は web の関門**: board.js は vitest 対象外——実ブラウザ＋本番 WS＋観戦で没収 cue を目視するまでが web の受け入れ。
- **deploy は別段**: wasm は作り直すが本番反映は Step 3。
