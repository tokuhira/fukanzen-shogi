## 0. 何を実現するか（設計正本＝方針 §1.6）

留まった相手駒を取ってマス S へ移ったとき、**移動完了時点**の S への利きを数える。守り側の利き数 **d**（取られた側で S に利く枚数）が攻め側の利き数 **a**（取りに行った駒を除く自分の駒で S に利く枚数）を上回るとき（**d ＞ a**）のみ、取りに行った駒を**相手の駒台へ没収**し S を空ける。取られた駒はそのまま自分の駒台へ（取得は成立）。**a ≧ d は現状のまま**（通常取得・駒は S に残る）。

一つの規則が二方針を担う: 没収が方針1（取り返しの代償で損得回復）、利きを足して a≧d を作れることが方針3（膠着打開への報酬＝突破）。別建ての反停滞層は無い（案A）。

## 1. 決定済みの設計（re-litigate しない）

- **判断1（非玉ガード）**: 取りに行った駒が玉のときは没収しない（玉は駒台に載らない）。移動後実支えゆえ玉取得で d>a が成立しうるが、それは 5.2 の領分で没収の対象外。
- **判断2（イベント）**: `ResolutionEvent::Normal` に `sente_forfeit: Option<PieceKind>`・`gote_forfeit: Option<PieceKind>` を足す（「解決の一形態」）。
- **判断3（判定時点）**: 支え・利きは**移動完了時点**で数える。**着手の合法性は着手開始時点のまま**（§3・無変更）。
- **後詰めの計数＝(b) 対称（串刺し方式）を採用**: 取り合いマス S の裏に控えた走り駒（後詰め）を、攻守どちらも数える。素の `piece_attacks` は S 上の取った駒（味方）に遮られ攻め側の後詰めを取りこぼすので、**S を空けた盤で両側を数える**（S を透かす）＝守り・攻めとも後詰めが利く。狙いは、後詰めを攻めに使えることで大駒・香の価値を将棋どおりに活かし、積極的な前進（後詰めを重ねて突破）を報いること（方針3）。※値と多段の取り合い順序は依然見ない（枚数のみ）。
- **X-b（置換で最小着地）**: `RULE_VERSION` を `(0,7)` へ上げ、`resolve_independent` を差し替える。**版ディスパッチ・legacy-play・v0.6 での対局は繰り延べ**（方針 §1.5 改訂）。v0.6 はルール仕様 v0.6 と git に完全に残る。
- **Y（段刻み）**: engine 核（盤面が正しくなる）を先行、没収の表示・棋譜・観戦は fast-follow。

## 2. 層の置き方

- **engine が正本**: `resolve_independent` の没収分岐＋`count_attackers`＋`Normal` 拡張＋`RULE_VERSION`。ルールの真実はここ一箇所。
- **版の伝播は自動**: `negotiate`（`protocol/src/negotiate.rs:64`）・`archive`（`engine/src/archive.rs:133`）は `RULE_VERSION` を読むので、定数を上げれば交渉・刻印は追随する。
- **表示は殻**: `engine-wasm` の event 文字列（`engine-wasm/src/lib.rs:44`）→ protocol → TUI/web の event 表示・棋譜表記・観戦配信。没収の可視化はここ（Step 2）。

## 3. 段組

- **Step 1（engine 核・要石）**: `count_attackers(pos, sq, side)` を movegen に追加、`ResolutionEvent::Normal` を没収2フィールドで拡張し全構築/match 箇所を追随、`resolve_independent` に没収分岐（**S を空けた盤で**両側 d/a を先に数えてから適用＝(b)・非玉ガード）、`RULE_VERSION`→`(0,7)`、版上げで破れる 2 テスト文字列（`engine-wasm/src/lib.rs:654`・`protocol/src/wire.rs:137`）を 0.7 へ、table テスト。**`cargo fmt`/`clippy -D warnings`/`test`（ci.yml 通り）でワークスペース緑**。→ 盤面状態が正しくなり v0.7 が指せる（没収の表示は未整備）。
- **Step 2（表示 fast-follow）**: 没収を engine-wasm の event へ載せ、TUI/web の event 表示・棋譜表記・観戦配信で「取得＋没収」を見せる。web `?v=` 更新。**実ブラウザ＋本番 WS 検証が必須**（board.js は vitest 対象外）。
- **Step 3（ルール正本の版上げ・着地時）**: **`design/不完全将棋_ルール仕様_v0.7.md` を新設**（v0.6 を土台に、§0 中核命題を更新〔支え付き駒の取得に取り返しの代償が生じ損得が働く〕・§4 に「支え付き取得の利き数没収」節を追加〔d>a のみ没収・(b) 串刺し・非玉ガード・移動完了時点で S を空けて数える〕・§6 差分表・§7／改訂履歴を更新）、**`design/…_ルール仕様_v0.6.md` → `archive/rule-history/` へ `git mv`**、README の A を v0.7 へ・B-1 の superseded 一覧へ v0.6 を追加。**v0.6 は deploy されている間は正本のまま**なので、この版上げは engine 実装が固まり deploy へ向かう段で行う（先んじて v0.6 を archive へ移すと、現に生きている正本が履歴に埋もれる）。
- **着地（deploy・Step 3 と同時）**: wasm 再ビルド（web/README.md 厳守）＋TUI リリース＋web デプロイ（wrangler）。**版が初めて上がる実イベント**——完全一致交渉ゆえ全クライアントが 0.7 へ揃わないと対局不成立。deploy 後、方針 §1.6 の観測条件で方針3 の毀損を playtest 観測。

## 4. 作らないもの（＝理由つき）

- **版ディスパッチ・版選択交渉**: X-b で繰り延べ（legacy-play が実際に欲しくなったとき・§1.5）。v0.6 は仕様と git に残す。
- **点数制**: 方針3 毀損が観測されてから分家 `0.7-点数` で（§1.6 観測条件）。今は利きの数だけ。
- **相討ち（4.3/4.4/4.7）の変更**: 投機を残す。取得（4.1）＝`resolve_independent` だけ触る。
- **没収の位置的取り返し**: S は空く・守り駒は動かない（方針 §1.6 の簡略化＝物質的で位置的でない）。
- **値・多段順序の勘定**: (b) でも枚数のみ（値と多段の取り合い順序は見ない）。そこの精密化は点数制（分家）の候補。

## 不変の原則

- **取得だけ・相討ちは無変更**: 4.1（`resolve_independent`）にのみ没収を足す。投機の手段＝相討ちは触らない。
- **移動完了時点で数え、合法性は着手開始時点**: 二つの時点を混ぜない（§3 は無変更）。
- **両側 d/a を先に数えてから適用**: 同ターン双方の支え付き取得で順序依存を出さない（resolve の同時性思想＝`resolve.rs:205-208` と一貫）。
- **玉は没収しない**: 非玉ガード。玉の死は 5.2 の領分。
- **engine が正本・版は自動追随・表示は殻**: ルールの真実は engine 一箇所、negotiate/archive は RULE_VERSION を読むだけ、表示は Step 2 の殻。
- **過ぎたるは及ばざる**: 版ディスパッチも点数も作らない。v0.6 は葬らず仕様と git に残す（X-b）。
